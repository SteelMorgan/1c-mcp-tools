# 1c-mcp-tools

Прикладное расширение 1С для размещения MCP tools, исполняемых внутри 1С.

Репозиторий содержит только исходники расширения:

- `src/1c_ext/` - XML-выгрузка расширения 1С;
- `src/1c_ext/agents.md` - краткие правила разработки tools внутри расширения.

Собранные `.cfe`, клиентские настройки, Docker-инфраструктура и Python-прокси из этого репозитория удалены. Этот проект больше не является самостоятельным прокси-сервером или транспортным слоем.

## Место в системе

`1c-mcp-tools` - прикладной слой в общей архитектуре MCP для 1С.

Транспорт, публикация и агрегация MCP-витрины живут в других компонентах:

- `v8-runner` запускает клиент 1С и передаёт параметры подключения к менеджеру сессий;
- `web-transport-addin` даёт WebSocket-канал из клиента 1С;
- `wt-mcp-adapter` регистрирует клиентские и серверные tools в 1С и публикует их через WS;
- `v8-session-manager` (`v8sm`) агрегирует tools всех подключённых 1С-сессий и отдаёт единую MCP-витрину агенту.
- [1c-masking-service](https://github.com/SteelMorgan/1c-masking-service) применяет правила маскирования к ответам перед выдачей агенту; менеджер обращается к его API.

Роль этого репозитория уже: хранить прикладные tools, которые будут размещаться в расширении 1С и исполняться в клиентском или серверном контексте через адаптер/менеджер.

## Что есть в расширении

Ключевые объекты:

- `mcp_Мсп_Провайдеры` - маркерная подсистема провайдера tools;
- `mcp_КонтейнерыИнструментов` - подсистема обработок, публикующих tools;
- `mcp_КонтейнерыРесурсов` - подсистема обработок, публикующих resources;
- `mcp_КонтейнерыПромптов` - подсистема обработок, публикующих prompts;
- `mcp_Метаданные` - сбор описаний tools/resources/prompts из контейнеров;
- `mcp_Выполнение` - диспетчеризация вызова в обработку-контейнер;
- `mcp_КонтейнерыПовтИсп` - получение текущего каталога tools/resources/prompts;
- `mcp_APIBackend` - legacy HTTP JSON-RPC/MCP endpoint, оставшийся от исходной реализации.

Текущие встроенные возможности:

**Публичные инструменты (10):**

| Инструмент | Назначение |
|---|---|
| `execute_query` | Выполнение запросов 1С с параметрами, лимитом строк и предварительной проверкой синтаксиса. |
| `get_metadata` | Структура и свойства объектов метаданных конфигурации. |
| `get_object_by_link` | Чтение объекта по навигационной ссылке. |
| `get_link_of_object` | Получение навигационной ссылки по описанию объекта. |
| `find_references_to_object` | Поиск ссылок на объект в выбранных разделах метаданных. |
| `get_access_rights` | Проверка прав доступа к объектам метаданных. |
| `get_storage_structure` | Физические таблицы, поля и индексы; обязателен конкретный фильтр имени таблицы или метаданных. |
| `get_report_settings` | Параметры СКД, встроенные варианты и сохранённые настройки текущего пользователя; без исполнения отчёта. |
| `run_scheduled_job` | Штатный запуск существующего регламентного задания и диагностика выполнений через БСП: `run`, `status`, `list`, `details`. |
| `mcp_diag_query_parse_bench` | Замеры разбора запросов, анализа происхождения колонок и обработки границы данных; измерение исполнения включается отдельно. |

**Внутренние инструменты сервиса маскирования (`visibility=internal`):**

- `mcp_internal_masking_metadata_feed` — ограниченная выдача метаданных;
- `mcp_internal_masking_dictionary_feed` — ограниченная выдача словарных данных.

Manager не публикует эти два инструмента агентам. Словарный `filter_ast`
проверяется по типам и разрешённым полям метаданных, затем превращается в
параметризованный отбор запроса 1С; wildcard разворачивается до вызова 1С.

**Ресурс:** `1csyntax` (`file://resource/syntax_1c.txt`) — справка по встроенному языку 1С.

## Граница данных и маскирование

Инструменты данных передают ответ через `mcp_ROCTUPГраницаДанныхСервер`
в согласованном конверте:

```json
{
  "schema_version": 1,
  "result": {},
  "field_sources": {"schema": {}, "lineage": []}
}
```

`result` содержит результат инструмента. В `field_sources` передаются описание
колонок, их типы и происхождение значений. Для `execute_query` расширение
анализирует запрос средствами платформы `СхемаЗапроса`, чтобы связать колонки
результата, включая псевдонимы, с исходными реквизитами. Эти сведения нужны
сервису для применения правил к данным, а не для отдельной проверки текста
запроса агентом. Проверка синтаксиса уже встроена в `execute_query` до исполнения.

В 1С необратимо вырезаются секреты — пароли, токены, ключи и значения реквизитов
с `РежимПароля`; вместо них передаётся `[SECRET_REMOVED]`. Внешний
[1c-masking-service](https://github.com/SteelMorgan/1c-masking-service)
отвечает за настраиваемые правила маскирования, обратимые токены, словари
и историю. Менеджер передаёт ему результат и `field_sources` до ответа агенту.

Если происхождение колонки не подтверждено, поддерживаемый контракт позволяет
передать пометки `unverified` и фактические `output_types`. При включённом
`strict_mode` сервис заменяет каждую такую ячейку целиком маскирующим токеном.
Это отличается от безусловного отказа всего запроса. Нарушения ограничений
границы данных, некорректный конверт и отказ сервиса по-прежнему не позволяют
выдать агенту исходные данные. Подробные правила и настройки находятся в
[документации сервиса](https://github.com/SteelMorgan/1c-masking-service#readme).

Транспорт и регистрация провайдера принадлежат `wt-mcp-adapter` и
`v8-session-manager`; здесь реализованы инструменты, граница данных и внутренние
feeds. Совместимость конверта и feeds должна сохраняться между компонентами.

Код ROCTUP перенесён из `ROCTUP/1c-mcp-toolkit`, commit
`fe12903af7a367a9d67dd055c13f4b59bb59d83c`, под GPL-3.0.
Атрибуции и условия стороннего кода перечислены в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Целевая модель развития

Новые tools размещаются как обработки-контейнеры внутри расширения.

Для tool-контейнера:

1. Создать обработку с префиксом `mcp_`.
2. Включить её в подсистему `mcp_КонтейнерыИнструментов`.
3. В модуле менеджера реализовать:

```bsl
Процедура ДобавитьИнструменты(Инструменты) Экспорт
	// Описать tools и их JSON schema через mcp_Метаданные.
КонецПроцедуры

Функция ВыполнитьИнструмент(ИмяИнструмента, Аргументы) Экспорт
	// Выполнить нужный tool и вернуть результат.
КонецФункции
```

Для resources и prompts используются те же принципы:

- контейнер resources включается в `mcp_КонтейнерыРесурсов`;
- контейнер prompts включается в `mcp_КонтейнерыПромптов`;
- описание и исполнение идут через экспортные методы контейнера.

Подробности текущего внутреннего API описаны в [`src/1c_ext/agents.md`](./src/1c_ext/agents.md).

## Происхождение

Технически этот репозиторий начался как форк проекта [RooLee10/1c-mcp-tools](https://github.com/RooLee10/1c-mcp-tools), который, в свою очередь, основан на оригинальном проекте [vladimir-kharin/1c_mcp](https://github.com/vladimir-kharin/1c_mcp).

Авторам исходных проектов - уважение и благодарность за основу и идею.

При этом в текущем репозитории существенная часть функциональности уже отломана от исходной реализации, переработана или будет заменяться. Поддерживать зависимость от upstream-проектов и сохранять совместимость с ними не планируется.

Дальше проект развивается как самостоятельное прикладное расширение в текущей архитектуре: площадка для размещения 1С MCP tools клиентского и серверного исполнения.

## Что не входит в проект

В этом репозитории больше нет:

- Python-прокси;
- Docker-образа прокси;
- `docker-compose.yml`;
- готового `build/*.cfe`;
- примеров настроек MCP-клиентов;
- batch-скриптов запуска HTTP-сервера.

Эти функции относятся к инфраструктуре запуска, транспорта и агрегации. Здесь остаётся только 1С-расширение с прикладными tools.

## Универсальная диагностика

- `get_storage_structure`: platform storage schema; нужен конкретный фильтр имени таблицы/метаданных, `meta_type` только дополнительный; поля/индексы по флагам, limit/truncated.
- `get_report_settings`: default/embedded настройки основной СКД и report-user saved storage текущего пользователя, bounded typed JSON; не выполняет отчёт, не читает чужое несохранённое UI-состояние.
- `run_scheduled_job`: универсальная БСП-обёртка run/status/list/details. Каноническое универсальное имя без префикса проекта; GBIG/OKX бизнес-зависимостей нет.

Для заданий требуется БСП: `РегламентныеЗаданияСлужебный` (проверка администрирования, ручной запуск, СвойстваФоновыхЗаданий, ПолучитьСвойстваФоновогоЗадания) и `РегламентныеЗаданияСервер.ПолучитьРегламентноеЗадание`. Штатные права БСП сохраняются; native fallback не предусмотрен. Retention ограничивает доступную историю, limit ограничивает JSON, не native чтение. Mask tokens передавать неизменными.
